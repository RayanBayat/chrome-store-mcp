# Security

This page lists what the server protects against, and every safety layer. For each layer it names the code that
enforces it and the test that guards it. To report a problem, see [SECURITY.md](../SECURITY.md).

## What we protect

- Your Google refresh tokens and client secret.
- Your store item: nobody should be able to publish, cancel or roll back without you knowing.
- Your Google account: the server should hold no more permission than it needs.

## Threats

| Threat                                                                                                                                       | Why it matters                                                          |
| -------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| **Prompt injection.** Someone writes text that tells the AI what to do. The easy place to do this is a store review, which anyone can write. | A tricked assistant could call a write tool. This is the main threat.   |
| **An assistant that makes a mistake**, without any attacker.                                                                                 | It could publish, roll back or upload the wrong thing.                  |
| **A bad argument.** A tool argument built to change the address of a request, or to read a file that is not a package.                       | It could reach other Google endpoints or leak a file.                   |
| **A leaked token.** A token that ends up in an error message, a result or a log.                                                             | Anyone who sees it could use your account.                              |
| **Too much permission.** A sign-in that is wider than needed.                                                                                | A bug or a stolen token would do more damage.                           |
| **A hostile or confused network answer.** A redirect, a very large answer, or a hung connection.                                             | It could send a token elsewhere, flood the model, or freeze the server. |
| **A tricked dialog.** Text with markup or control characters that makes a dialog look different from what will happen.                       | The person might approve something they did not mean to.                |

### What we do not protect against

- Someone who already controls your computer or your Google account.
- `CWS_CONFIRM=none`. It removes the human check on purpose.
- Secrets in environment variables. They sit in plain text in your MCP settings. The Linux keyring is safer.
- Anything inside Google's services.
- Bugs in Node.js or in the dependencies (two runtime packages, pinned to exact versions).

backup: an empty file is already refused by the ZIP-header check.

## Rules for changing a guard

A **guard** is any code in the table above. If you change one, you must add or update a test that **fails when the
guard is removed or broken**. Prove it: break the guard on purpose, run `npm test`, see the test fail, then put the guard
back. See [CONTRIBUTING.md](../CONTRIBUTING.md).

## What the server never does

- It never sends a request to any host other than `chromewebstore.googleapis.com` (store), `oauth2.googleapis.com`
  (tokens and revoking) and `accounts.google.com` (the consent page that `login` opens in your browser).
- It sends no telemetry and writes no files.
- It never gives a token to the AI model. Tokens are used inside the server only.
